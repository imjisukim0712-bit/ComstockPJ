# 웹 창모드 UI 검증

## 수정 원칙

- 인게임 화면은 `UiCanvasLayout`이 1920×1080 설계 좌표로 맞춘다. 기존 타이틀 스케일러와 씬·프로젝트 설정은 유지한다.
- 레이아웃 계산은 화면 픽셀 대신 RectTransform의 설계 좌표를 사용한다. 월드 추적 UI만 화면 좌표를 캔버스로 변환한다.
- 창 크기 변화에 따른 상점 재배치는 CanvasScaler가 갱신된 뒤인 LateUpdate에서 한다.
- 웹빌드 완료 시 `WebGlWindowLayout`이 index.html에 16:9 자동 맞춤을 넣는다. 기존 Unity 하단 바는 숨기며 전체화면 전환은 게임 설정을 사용한다.

## 에디터 검사

`Probe.cs`는 플레이 모드에서 Unity MCP의 script-execute로 실행하는 검증용 코드다. Assets 밖에 있으므로 실제 게임에 포함되지 않는다.

도구가 준비된 경우 프로젝트 루트에서 다음처럼 실행한다.

```powershell
./dev/web-ui/Invoke-Unity.ps1 -CodePath dev/web-ui/Probe.cs -ClassName WebUiVerification20260831
```

- 한국어·영어 각각 1920×1080, 960×600, 960×540, 640×360, 800×600.
- 타이틀, 언어, 설정, 랭킹, 도감, 머리 선택, HUD, 일시정지, 일시정지 설정, AI 코어, 정비, 상점, 장비 상세, 새로고침, 구매 소켓 선택, 결과, 닉네임, 클리어 정산.
- 6소켓 로봇의 상점을 연 채 1920×1080 → 960×540 → 640×360 → 2560×1440 → 1920×1080 변경.
- 상점 재개방과 골드 0, 1, 1234567 표시.
- 결과는 `Builds/UI-verification/report.json`, 캡처는 같은 폴더의 PNG. `error.txt`가 비어 있고 `done.txt`가 완료 시각이어야 검증 완료다.
- 진행 중 결과 파일을 읽지 않는다. Windows에서 파일 읽기/쓰기 충돌이 생길 수 있으므로 전체 결과는 종료 시 한 번 저장한다.
- 언어 선택과 해금 저장값은 검증 전 값을 보관하고 종료 시 복구한다. 기존 플레이는 종료하고 테스트용 플레이 모드에서 실행한다.

## 웹빌드

`Build.cs`는 에디터가 플레이 모드가 아닐 때 실행한다. 활성화된 빌드 씬과 현재 WebGL 프로젝트 설정을 그대로 사용하여 `Builds/ComstockWebUI`에 출력한다.

```powershell
./dev/web-ui/Invoke-Unity.ps1 -CodePath dev/web-ui/Build.cs -Timeout 600000
```

장시간 빌드 중 MCP 연결만 끊길 수 있다. 이 경우 다시 빌드를 시작하지 말고 `build-result.txt`와 Unity 로그를 확인한다. Unity 내부 빌드는 계속 진행될 수 있다.

로컬 확인은 HTTP 서버를 사용한다. `index.html`을 파일 탐색기에서 더블클릭하면 Unity 데이터 다운로드가 실패한다.

itch.io에 재업로드할 때 ZIP 최상위에 `index.html`, `Build`, `TemplateData`가 있어야 한다. 상위 폴더 전체를 한 단계 감싸서 압축하지 않는다.
