# 컴스톡 쇼츠 「Dam Dididi」 - 만드는 법

레퍼런스 <https://www.youtube.com/shorts/7Il55sXlulw> 의 구성을 그대로 따르되
**고양이 자리에 컴스톡 로봇**을, **오른쪽 품목 자리에 게임 리소스**를 넣은 9초 세로 영상.

| 레퍼런스 | 우리 | 판정 |
|---|---|---|
| 술 & 담배 | **좀비**(좀비 / 스피터 / 차저 / 스프린터) | ✗ 빨강 |
| 패스트푸드 | **무기**(HMG / 로켓런처 / 컴뱃샷건 / 체인소드) | ✓ 초록 |
| 과자칩 | **디스크**(01 / 18 / 05 / 12) | ✓ 초록 |
| 돈 | **골드 / 경험치 / 부품상자**(`Gold.png` `Exp.png` `ItemBox.png`) | ✓ 초록 |

화면 상단에는 제목이 9초 내내 떠 있다 - 한글판 **"컴스톡의 취향"**, 영문판 **"Comstock's Tastes"**
(`short_common.LANG`, `--lang {ko,en}`).

## 준비물

`Pillow`, `numpy`, `ffmpeg`(PATH에 있어야 한다), 그리고 **Git LFS로 받아 둔 스프라이트**.
`Assets/Resources/*.png`가 LFS 포인터 상태(파일이 130바이트쯤)면 먼저 `git lfs pull`.

**원곡**(`assets/damdidi_original.mp3`)이 있어야 기본 렌더가 된다. 제3자 저작물이라
저장소에 넣지 않았으므로(`.gitignore`) 파일을 그 경로에 직접 둔다.
없으면 `--game-audio`(게임 BGM/효과음)나 `--silent`를 쓴다.

## 실행

```
cd dev/short
python analyze_song.py                           # 원곡에서 박자 격자 실측 (근거 재현)
python render_short.py --contact                 # 전체 흐름 한 장으로 확인 (몇 초)
python render_short.py --frames 27,105,165,240   # 특정 프레임만 png로
python render_short.py                           # 원곡을 얹은 mp4 (기본, 약 25초)
python render_short.py --lang en --out Comstock_DamDidi_EN.mp4     # 영문 제목판
python render_short.py --silent --out Comstock_DamDidi_silent.mp4  # 무음본
python render_short.py --game-audio              # 게임 BGM/효과음판
python verify_short.py                           # 픽셀·박자로 재는 검증 (약 60초)
```

출력은 **1080x1920 / 30fps / 8.73초(262프레임) / H.264 CRF 18 + AAC 192k + faststart**,
약 1.9MB. 길이는 원곡에 맞춘 것이다.

## 파일

| 파일 | 역할 |
|---|---|
| `short_common.py` | 화면 규격, 배치 좌표, 타임라인, 구간별 품목표 |
| `short_draw.py` | 에셋 캐시, 로봇 모션, 품목 뭉치, O/X 판정 그리기 |
| `render_short.py` | 프레임 렌더 + ffmpeg 인코딩 (콘택트시트/단일 프레임 모드 포함) |
| `build_short_audio.py` | 게임 BGM/효과음으로 9초 오디오 트랙 |
| `analyze_song.py` | 원곡에서 박자 주기와 **위상**을 실측(BEAT / T0 / NF의 근거) |
| `verify_short.py` | 화면 밖 침범 / 겹침 / 모션 / 판정 색 / 제목 / **박자 정합**을 재서 검사 |
| `레퍼런스_실측.md` | 레퍼런스에서 무엇을 어떻게 쟀는지 |

## 고칠 때 알아 둘 것

- **품목 개수는 구간마다 달라도 된다**(골드 구간은 3개짜리 삼각 배치다). `ITEMS`의
  항목 수와 `CLUSTERS`의 칸 수만 맞으면 된다.
- **품목을 바꾸려면** `short_common.py`의 `ITEMS`만 고치면 된다. 크기는 칸의 **넓이**에
  맞춰지므로(`short_draw.fit`) 가로로 긴 그림을 넣어도 배치가 안 무너진다.
  다만 유난히 넓은 그림을 넣었다면 `ITEM_BOXES` / `ITEM_CXS` / `CLUSTERS`로 그 구간만
  따로 조정하고, **반드시 `verify_short.py`를 돌려** 화면 밖으로 나가지 않는지 확인할 것.
- **★ 박자 상수(`BEAT` / `T0` / `NF`)는 손으로 정한 값이 아니라 원곡 실측값이다.**
  `analyze_song.py`가 온셋 포락선에 16박 격자를 맞춰 뽑는다(110.3 BPM, 첫 박 0.110초).
  음원을 바꾸면 그 스크립트를 다시 돌려 세 값을 갱신해야 한다 - 안 그러면 도장이 박에서
  어긋난다. `verify_short.py` 7번 항목이 코드값과 음원을 대조해서 잡아 준다.
- **★ 구간 내부 시각도 박에 붙여 둔다.** `SEG_MARK = BEAT`(2박째), `SEG_OUT = 3.25 * BEAT`.
  절대초로 두면 박자를 바꿀 때 같이 안 움직여서 0.05초씩 어긋난다 - 음악 위에서는
  그 정도도 "박자를 놓친" 것으로 들린다.
- **★ 로봇을 더 키우고 싶다면 화면 왼쪽 끝을 먼저 재라.** `Comstock.png`는 팔을 벌린
  가로 1.78:1이라 이미 폭 590px(스쿼시·기울기·확대 최대에서 12~680px)을 쓴다. 여기서 더
  키우면 마체테 끝이 잘린다 - 실제로 골드 구간 확대를 1.25배로 잡았다가 왼쪽 가장자리를
  22px 침범해서 낮춘 전례가 있다(`verify_short.py`가 잡아냈다).
  **로봇을 키우면 품목 자리가 그만큼 줄어든다** - 둘이 가로를 나눠 쓴다. 520 → 590으로
  키울 때 스쿼시 6→5% / 기울기 2.4→2.0° / 골드 확대 1.10→1.05로 "가로로 부푸는 양"을
  줄이고, 모자란 움직임은 튀는 높이(3.5→4.2%)로 벌충했다.
- **★ 상단 제목의 글자 크기는 언어마다 다시 잰다.** 같은 84pt인데 "컴스톡의 취향"은
  476px, "Comstock's Tastes"는 **950px 이상**으로 화면(1080)을 거의 꽉 채운다. `draw_title`이
  `TITLE_MAX_W`(880) 안에 들어올 때까지 크기를 낮춘다 - 한국어만 보고 정하면 영문에서
  가장자리까지 밀린다. 한글은 Orbitron이 라틴 전용이라 **NotoSansKR**이 받는다.
- **다른 음원을 얹고 싶으면** 무음본에 오디오만 갈아 끼우면 된다(박자는 안 맞는다).
  `ffmpeg -i Comstock_DamDidi_silent.mp4 -i 노래.m4a -c:v copy -c:a aac -shortest 결과.mp4`

## mp4는 커밋하지 않는다

원곡 mp3도 같이 뺐다(제3자 저작물). 영상은 `dev/pv` 때와 같은 방침이다. `.gitattributes`에 `*.mp4` LFS 규칙이 없어서 영상을 그대로
커밋하면 일반 blob으로 들어간다(다른 바이너리는 전부 LFS인데 영상만 예외가 된다).
스크립트만 있으면 **25초 만에 다시 만들 수 있으므로** `.gitignore`로 빼 뒀다.
저장소에 넣어야 한다면 `.gitattributes`에 `*.mp4 filter=lfs diff=lfs merge=lfs -text`를
추가하는 판단이 먼저 필요하다(프로젝트 설정 변경이라 사용자 확인 대상).
