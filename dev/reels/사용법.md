# 컴스톡 세로 릴스(인스타 릴스 / 틱톡) 만들기

`dev/pv/`(가로 40초 PV)와 같은 방식이다 — **유니티를 켜지 않고** Python(Pillow)이
`Assets/Resources`의 스프라이트로 프레임을 그리고 ffmpeg이 인코딩한다.
다른 점은 **세로 9:16 / 15초 / 밈 포맷**이라는 것.

## 원본 영상을 쓰지 않는 이유

참고로 받은 <https://youtu.be/CdAk5i71gdo>("Damdam Didi didi cat", @mixedmemes-exe)는
**제3자의 유튜브 업로드**다. 그 파일을 받아서 얼굴만 갈아 끼워 릴스/틱톡에 올리면
남의 영상을 재업로드하는 것이라 저작권 신고·계정 제재 대상이 된다.

그래서 **영상이 아니라 밈의 "형식"만 가져왔다** — 흰 배경, 오려낸 얼굴 하나,
비트마다 찌그러졌다 튀어오르는 스쿼시. 그 위에 우리 로봇 머리 12종을 올려
프레임을 처음부터 새로 그린다. 밈 마케팅에서 원래 쓰는 방식이고, 결과물은 100%
우리 에셋이라 어디에 올려도 걸릴 게 없다.

## 결과물

| 파일 | 용도 |
|---|---|
| `Comstock_Reel_EN.mp4` / `_KO.mp4` | **무음판.** 릴스/틱톡 앱에서 유행하는 사운드를 직접 붙일 때 |
| `Comstock_Reel_EN_beat.mp4` / `_KO_beat.mp4` | **비트판.** 그대로 올려도 되는 자체 제작 칩튠 |

전부 1080x1920 / 30fps / 15.00초 / H.264 High + yuv420p / AAC 스테레오 48kHz,
약 4MB. 릴스·틱톡·쇼츠가 모두 그대로 받는 규격이다.

**무음판에도 무음 오디오 트랙을 일부러 넣어 뒀다** — 오디오 스트림이 아예 없는 mp4를
거부하는 업로더가 있다.

## 올리는 법

- **무음판 + 앱에서 사운드 붙이기**(권장) — 유행하는 음원은 앱 안에서 붙여야
  그 음원의 탐색 피드에 실린다. 원본 밈의 음원을 붙이고 싶다면 이 방법뿐이다.
  파일에 음원을 박아서 올리면 탐색에 안 실리고 저작권 판정만 받는다.
- **비트판 그대로 올리기** — 음원을 안 고르고 바로 올릴 때.

## 실행

```bash
cd dev/reels
python3 render_reel.py all --beat        # EN/KO x (무음판+비트판) = 4개, 약 2분
python3 render_reel.py en                # EN 무음판만
python3 build_beat.py                    # 비트 트랙(wav)만
python3 render_reel.py en --preview 0.03,4,8,11.6,13.3   # 그 시각 프레임만 PNG로
```

필요한 것: Python 3 + Pillow + ffmpeg. ffmpeg은 PATH → 환경변수 `FFMPEG` →
`pip install imageio-ffmpeg` 번들 순으로 찾는다(`reel_common.ffmpeg_exe`).

**머리 PNG는 Git LFS에 있다.** 새 클론에서는 `git lfs pull` 먼저 하지 않으면
Pillow가 "cannot identify image file"을 낸다(파일 내용이 포인터 텍스트라서 그렇다).

## 구성 (8마디 / 15.00초)

BPM 128, 한 마디 1.875초. 마디 안에서 얼굴이 튀는 시각은
`HITS_IN_BAR = (0, 1, 2, 2.5, 3, 3.5)` 4분음표 단위 — 이게 **"담-담-디디-디디"**다.

| 마디 | 시각 | 화면 |
|---|---|---|
| 0~1 | 0.00~3.75 | 얼굴 1개(네온아이) |
| 2~3 | 3.75~7.50 | 2개 |
| 4~5 | 7.50~11.25 | 4개 |
| 6 | 11.25~13.13 | 12개 전원 |
| 7 | 13.13~15.00 | 12개 + 제목 카드 슬램 |

앞 마디 얼굴은 그대로 두고 새 얼굴이 합류한다(`render_reel.CAST`).
얼굴이 4개 이하면 히트마다 **한 칸씩 주고받으며** 튀고, 12개면 **다 같이 물결로** 튄다
(`reel_draw.hit_state`).

## 고칠 때 알아야 할 것

- **★ 시각을 초로 박지 말 것.** 장면 길이·히트·엔드카드가 전부 `BPM`에서 파생된다.
  다른 곡에 맞추려면 `reel_common.BPM` **한 곳만** 고치면 영상과 비트가 함께 따라온다.
  (`dev/pv/`는 절대시각을 하드코딩해서 길이를 바꿀 때마다 효과음 64발을 손으로
  옮겨야 했다 — 그 함정을 안 물려받으려고 이렇게 짰다.)
- **★ 비트 트랙도 같은 `HITS`를 읽는다**(`build_beat.py`). 좌표를 두 벌 관리하지
  않으니 얼굴 튐과 드럼이 어긋날 수가 없다. 검증도 이걸로 한다 — 합성한 wav의
  온셋을 뽑아 `HITS` 48개와 대조했다(누락 0).
- **★ 노란 링은 스탬프에 한 번만 굽는다**(`reel_draw._make_stamp`). 프레임마다
  `MaxFilter`를 돌리면 렌더가 몇 배로 느려진다. 링 두께는 스탬프와 함께 축소되므로
  **얼굴 크기 대비 비율로 고정**된다 — 16px(1.8%)은 12개 격자에서 서로 닿아
  지저분했고 10px(1.1%)이 한 얼굴에서도 격자에서도 버틴다.
- **★ 900px 스탬프를 매 프레임 300px로 줄이면 그게 렌더 시간의 대부분이다.**
  `_sized_stamp()`가 슬롯 크기의 1.3배로 한 번만 줄여 캐시한다. 카메라 펄스 때문에
  크기가 매 프레임 미세하게 달라지므로 **16px 단위로 뭉쳐서** 캐시한다.
- **★ 한글 줄에 Orbitron을 쓰면 두부가 된다**(라틴 전용 207자). `LANG`에서 줄마다
  폰트를 따로 지정하는 이유다 — 제목/URL은 Orbitron, 한글 문구는 NotoSansKR.
- **안전 띠**: 인스타 릴스는 위/아래에 자기 UI를 겹쳐 그린다. 얼굴과 글자는
  `SAFE_TOP 260 ~ SAFE_BOTTOM 1560` 안에만 놓는다.
- 문구를 바꾸려면 `reel_common.LANG`만 고친다. 코드 어디에도 언어 분기가 없다.
- **게임 코드·씬·에셋은 건드리지 않는다.** 이 폴더는 읽기만 한다.
