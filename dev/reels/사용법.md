# 컴스톡 세로 릴스(인스타 릴스 / 틱톡) 만들기

`dev/pv/`(가로 40초 PV)와 같은 방식이다 — **유니티를 켜지 않고** Python(Pillow)이
`Assets/Resources`의 스프라이트로 프레임을 그리고 ffmpeg이 인코딩한다.
다른 점은 **세로 9:16 / 17.5초 / 밈 포맷**이고, 얼굴 튐이 **음원의 박자에
묶여 있다**는 것이다.

## 원본 영상을 쓰지 않는 이유 (그림은 전부 새로 그린다)

참고로 받은 <https://youtu.be/CdAk5i71gdo>("Damdam Didi didi cat", @mixedmemes-exe)는
**제3자의 유튜브 업로드**다. 그래서 **영상 프레임은 한 장도 쓰지 않았다** — 밈의
"형식"(흰 배경, 오려낸 얼굴 하나, 비트마다 찌그러졌다 튀어오르는 스쿼시)만 가져와
우리 로봇 머리 12종으로 처음부터 새로 그린다. 입력 영상이 없고
`Assets/Resources/Heads`의 PNG만 읽는다.

## 음원 (`music/` — 깃에 안 올린다)

`_music` 판에는 **사용자가 준 원본 밈 음원**이 들어간다. 이건 남의 저작물이므로
**저장소에 커밋하지 않는다**(`.gitignore`의 `music/`). 렌더하려면 각자
`dev/reels/music/meme_source.mp3`에 파일을 놓아야 한다 — 없으면 렌더가 그렇게 알려준다.

업로드 시 참고: 이 판은 음원이 파일에 박혀 있어서 **그 음원의 탐색 피드에는 안 실리고**,
플랫폼 Content ID에 잡히면 음소거·수익화 제한·지역 차단이 걸릴 수 있다. 그게 싫으면
무음판을 올리고 앱 안에서 같은 음원을 고르면 된다. 어느 쪽을 쓸지는 올리는 사람이 정한다.

## 결과물

| 파일 | 용도 |
|---|---|
| `Comstock_Reel_EN_music.mp4` / `_KO_music.mp4` | **원본 음원판.** 밈 음원이 박혀 있다 |
| `Comstock_Reel_EN.mp4` / `_KO.mp4` | **무음판.** 앱에서 사운드를 직접 붙일 때 |
| `Comstock_Reel_EN_beat.mp4` / `_KO_beat.mp4` | **비트판.** 저작권 걱정 없는 자체 제작 칩튠 |

전부 1080x1920 / 30fps / 17.51초 / H.264 High + yuv420p / AAC 스테레오 48kHz,
약 4~5MB. 릴스·틱톡·쇼츠가 모두 그대로 받는 규격이다.

**무음판에도 무음 오디오 트랙을 일부러 넣어 뒀다** — 오디오 스트림이 아예 없는 mp4를
거부하는 업로더가 있다.

## 올리는 법

- **원본 음원판 그대로 올리기** — 손이 제일 덜 간다. 위 "음원" 절의 주의사항을 감수할 때.
- **무음판 + 앱에서 사운드 붙이기** — 그 음원의 탐색 피드에 실리고 Content ID도 안 탄다.
  영상이 음원 박자에 맞춰져 있으므로 **앱에서 같은 음원을 고르고 시작점만 0초에 맞추면**
  그대로 맞는다.
- **비트판 그대로 올리기** — 저작권을 아예 안 건드릴 때.

## 실행

```bash
cd dev/reels
python3 render_reel.py all --music --beat # EN/KO x (무음+음원+비트) = 6개, 약 4분
python3 render_reel.py ko --music         # KO 무음판+음원판만
python3 build_beat.py                     # 자체 비트 트랙(wav)만
python3 analyze_audio.py <음원>           # 새 음원의 BPM/첫 박 재기
python3 render_reel.py en --preview 0.03,4,8,11.6,13.3   # 그 시각 프레임만 PNG로
```

필요한 것: Python 3 + Pillow + ffmpeg. ffmpeg은 PATH → 환경변수 `FFMPEG` →
`pip install imageio-ffmpeg` 번들 순으로 찾는다(`reel_common.ffmpeg_exe`).

**머리 PNG는 Git LFS에 있다.** 새 클론에서는 `git lfs pull` 먼저 하지 않으면
Pillow가 "cannot identify image file"을 낸다(파일 내용이 포인터 텍스트라서 그렇다).

## 구성 (8마디 / 17.51초)

**★ BPM·첫 박·마디 안 세기 분포는 지어낸 값이 아니라 원본 음원을 재서 넣은 것이다**
(`analyze_audio.py`). 온셋 피크 69개가 전부 8분음표 격자에 붙었고(평균 오차 36ms),
8마디가 음원 길이 17.461초와 거의 정확히 맞아떨어졌다 — 이 클립은 **109.855BPM 8마디**다.

한 마디 2.1847초, 첫 박 `AUDIO_OFFSET = 0.036`초. 마디 안 히트는 8분음표 8개인데
**4분음표 4개가 세고(1.0) 그 사이 엇박이 중간(0.55)** 이다 — 음원의 실측 세기 분포
그대로다. (처음엔 "담담 디디디디"로 짐작해 `(0,1,2,2.5,3,3.5)`를 썼는데, 실제로 재 보니
네 박이 고르게 세고 엇박이 받쳐 주는 형태였다. **짐작을 측정으로 교체했다.**)

| 마디 | 시각 | 화면 |
|---|---|---|
| 0~1 | 0.04~4.41 | 얼굴 1개(네온아이) |
| 2~3 | 4.41~8.78 | 2개 |
| 4~5 | 8.78~13.14 | 4개 |
| 6 | 13.14~15.33 | 12개 전원 |
| 7 | 15.33~17.51 | 12개 + 제목 카드 슬램 |

앞 마디 얼굴은 그대로 두고 새 얼굴이 합류한다(`render_reel.CAST`).

**센 박과 엇박을 다르게 쓴다** — 센 박에서는 얼굴이 4개 이하면 **한 칸씩 주고받고**
12개면 다 같이 물결로 튄다. 엇박에서는 주고받기 없이 **전원이 작게** 튄다. 그래야 리드가
박을 주고받는 동안에도 화면 전체가 음악에 붙어 있다(`reel_draw.hit_state`).

## 고칠 때 알아야 할 것

- **★ 시각을 초로 박지 말 것.** 장면 길이·히트·엔드카드가 전부 `BPM`/`AUDIO_OFFSET`에서
  파생된다. **음원을 바꾸면 `analyze_audio.py`를 돌려 그 두 값만 갈아 끼우면** 영상·비트가
  통째로 따라온다. (`dev/pv/`는 절대시각을 하드코딩해서 길이를 바꿀 때마다 효과음 64발을
  손으로 옮겨야 했다 — 그 함정을 안 물려받으려고 이렇게 짰다.)
- **★ 외부 음원을 그냥 얹으면 박자가 어긋난다.** 얼굴 튐은 `HITS` 격자에 묶여 있고
  그 격자는 음원의 실제 템포·첫 박과 맞아야 한다. `analyze_audio.py`가
  스펙트럼 플럭스 온셋 → 자기상관 템포 → 펄스 열 위상으로 그 둘을 재 준다.
  **자기상관만으로는 박 위상이 16분음표 하나만큼 어긋날 수 있다** — 실제로 처음에
  그렇게 나왔고, 마디 안 세기 분포를 접어 보고 4분음표 자리에 세기가 몰리도록
  다시 잡아야 했다. 최종 검증은 음원 온셋 69개와 영상 히트 64개의 거리로 한다
  (중앙값 31.5ms, 97%가 80ms 이내).
- **★ 길이는 `-shortest`가 아니라 `-t`로 못 박는다.** `anullsrc`/`apad`는 무한 스트림이라
  `-c:v copy`와 같이 쓰면 `-shortest`가 안 먹고 ffmpeg이 무음을 영원히 인코딩한다
  (실제로 14분간 안 끝나서 죽여야 했다 - CPU만 타고 파일 크기는 안 늘어난다).
  `-t`는 어떤 오디오 소스든 정확히 영상 길이에서 끊어 준다.
- **★ `_cache/video_*.mp4`는 타이밍을 바꾸면 반드시 지울 것.** 영상은 언어당 한 번만
  인코딩해 캐시에 두고 오디오만 갈아 붙이는데, `BPM`을 바꾸고도 캐시가 남아 있으면
  **옛 격자로 만든 영상에 새 음원을 붙이게 된다**. 한 번 당했다 - 15초짜리 옛 KO 영상이
  캐시에 남아 있었다. 길이(`ffmpeg -i`의 Duration)로 확인하면 바로 보인다.
- **★ 비트 트랙도 같은 `HITS`를 읽는다**(`build_beat.py`). 좌표를 두 벌 관리하지
  않으니 얼굴 튐과 드럼이 어긋날 수가 없다.
- **★ 노란 링은 스탬프에 한 번만 굽는다**(`reel_draw._make_stamp`). 프레임마다
  `MaxFilter`를 돌리면 렌더가 몇 배로 느려진다. 링 두께는 스탬프와 함께 축소되므로
  **얼굴 크기 대비 비율로 고정**된다 — 16px(1.8%)은 12개 격자에서 서로 닿아
  지저분했고 10px(1.1%)이 한 얼굴에서도 격자에서도 버틴다.
- **★ 900px 스탬프를 매 프레임 300px로 줄이면 그게 렌더 시간의 대부분이다.**
  `_sized_stamp()`가 슬롯 크기의 1.3배로 한 번만 줄여 캐시한다. 카메라 펄스 때문에
  크기가 매 프레임 미세하게 달라지므로 **16px 단위로 뭉쳐서** 캐시한다.
- **★ 한글 줄에 Orbitron을 쓰면 두부가 된다**(라틴 전용 207자). `LANG`에서 줄마다
  폰트를 따로 지정하는 이유다 — 제목/URL은 Orbitron, 한글 문구는 NotoSansKR.
- **안전 띠**: 인스타 릴스는 위/아래에 자기 UI를 겹쳐 그린다. 얼굴과 글자는
  `SAFE_TOP 260 ~ SAFE_BOTTOM 1560` 안에만 놓는다.
- 문구를 바꾸려면 `reel_common.LANG`만 고친다. 코드 어디에도 언어 분기가 없다.
- **게임 코드·씬·에셋은 건드리지 않는다.** 이 폴더는 읽기만 한다.
