# 컴스톡 PV (15초 양산형 모바일 게임 광고)

어디서 본 것 같은 모바일 게임 광고의 문법을 그대로 흉내 낸 15초 세로 영상과 그 렌더러다.
게임에 실제로 들어 있는 스프라이트·BGM·효과음만 재료로 쓰고, 프레임을 한 장씩 합성한 뒤
ffmpeg로 MP4를 뽑는다. **Unity를 켜지 않아도 돌아간다.**

## 결과물

| 파일 | 설명 |
|---|---|
| `out/comstock_pv.mp4` | 본편. 15.0초 · **1080x1920 세로(9:16)** · 30fps · 약 14MB |
| `out/comstock_pv_web.mp4` | 웹 삽입용 경량본(720x1280, 약 3.6MB) |
| `out/comstock_pv.html` | 영상 + 컷별 콘티 + 제작 노트가 든 한 장짜리 페이지 |
| `out/still_*.png` | 확인용 정지 프레임 |

`out/`은 `.gitignore` 대상이다(생성물이며 용량이 크다).

**세로인 이유**: 이 장르는 비율 자체가 신호다. 9:16 화면에 조이스틱과 스킬 버튼이 깔려
있으면 내용을 보기도 전에 "모바일 게임 광고"로 읽힌다. 가로가 필요하면 이 영상을 16:9
가운데 놓고 양옆을 블러로 채우면 된다 — 실제 광고들이 유튜브에 올릴 때 쓰는 방식이라
오히려 더 그럴듯해진다.

## 실행

에셋이 **Git LFS**로 관리되므로 포인터 파일 상태면 PNG를 열 수 없다. 먼저 받아야 한다.

```bash
git lfs pull

pip install pillow numpy imageio-ffmpeg   # ffmpeg 바이너리 포함
python3 PV/make_pv.py                     # 본편 렌더 (약 2분 40초)
python3 PV/make_pv.py --stills            # 확인용 정지 프레임만
python3 PV/make_pv.py --preview 7.5       # 특정 시각 한 장만
python3 PV/build_page.py                  # 공유용 HTML 페이지
```

## 컷 구성 (총 15.0초 = 450프레임 @ 30fps)

| 시각 | 컷 | 화면 문구 | 흉내 낸 클리셰 |
|---|---|---|---|
| 00.0 | 훅 | 이게 진짜 무료라고? / 설치 1분 만에 만렙 | 첫 1초에 가짜 조작 UI와 손가락 커서 |
| 01.5 | 방치형 | 폰 꺼놔도 알아서 렙업! → 접속만 해도 Lv.999 | AUTO 토글, 레벨 1→999 롤링, 골드 비 |
| 03.4 | SSR 뽑기 | 100연차 무료 → ★★★★★ 전설등급 획득! | 암전 → 무지개 광선 → 폭발 → 등장 |
| 05.6 | 무기 자랑 | 무기 65종 전부 무료 지급 (진짜로) | 등급 카드가 위에서 우수수 |
| 07.3 | 가짜 선택지 | 당신의 선택은? → 실패! → 정답: 둘 다 장착 | 3초 카운트다운 + 오답 연출 |

| 13.1 | CTA | 지금 플레이! / 선착순 마감까지 00:0X | 뛰는 버튼, 무료 리본, 초소형 면책 |

**사실과 연출의 경계**: `무기 65종`은 프로젝트의 실제 사양이다. 반면 **랭킹·리뷰·별점·
다운로드 수·100연차·선착순은 전부 연출**이며 게임에 존재하지 않는다. 마지막 2초의
초소형 글씨가 이를 그대로 고지한다(장르 클리셰이자 진짜 고지).

## 구조

- 세로 9:16(1080x1920), 30fps.
- 장면은 `TIMELINE`이 `(시작초, 길이, 함수, 이름)`으로 들고 있다. 각 함수는 그 장면
  안에서 흐른 초를 받아 캔버스 한 장을 돌려준다.
- **가짜 조작 UI**(`draw_hud`)는 실제 게임의 UI 아트(`Resources/UI/`)로 조립한다.
  조이스틱·스킬버튼 4개·체력바·재화 패널·AUTO 토글·웨이브 표시. 안 바뀌는 부분은
  `hud_static()`이 한 번만 그려 캐시한다.
- **자막**(`fancy_text`)은 3겹이다: 굵은 검은 외곽선 → 흰 테두리 → 금색 그라데이션 속살.
- 후처리(`post`)는 줌 펀치 → 화면 흔들림 → 채도 +34% → 대비 → 블룸 → 비네팅 →
  컷 플래시 순이다.
- 소리는 `build_audio()`가 ffmpeg `filter_complex` 한 방에 섞는다.

## 겪은 함정 (다음에 또 걸리기 쉬운 것들)

- **★ 9-슬라이스 UI 패널을 `box`로 맞추면 정사각형으로 쪼그라든다.** `box=(w,h)`는 비율을
  유지한 채 사각형 **안에** 넣는 옵션이라, 정사각형 패널 스프라이트를 880x150 자리에
  넣으면 150x150이 된다(랭킹 행이 전부 작은 갈색 상자로 나왔던 이유). UI 패널·버튼은
  늘어나는 게 정상이므로 `size=(w,h)`로 **비율을 무시하고 늘여야** 한다.
  반대로 그림(무기·몬스터)은 `box`가 맞다.
- **연속 프레임을 프레임마다 따로 알파 bbox로 자르면 안 된다.** 실루엣이 변하는
  애니메이션은 프레임마다 bbox가 달라서, 각자 잘라 같은 높이로 그리면 그림이 매 프레임
  튄다. `seq()`가 **전체 프레임의 합집합 bbox로 한 번에** 자르는 이유다.
- **글꼴에 없는 특수문자는 빈 네모로 나온다.** `①②`와 `★`을 Orbitron(라틴 전용)으로
  그려서 네모가 됐다. `★`은 NotoSansKR에 있으니 `kr=True`로 그리고, `①②`처럼 애매한
  글자는 아예 `1` `2`로 바꿨다.
- **폭발은 주인공보다 앞에 그려야 한다.** 보스 폭사 연출을 로봇보다 먼저 그렸더니
  화면에서 사라졌다.
- **HUD 숫자는 자릿수가 늘어나면 패널을 넘는다.** 골드가 9자리가 되자 옆 패널까지
  침범했다. 폭 상한(352px)을 두고 넘치면 줄여서 그린다.
- **스킬 버튼을 각도 계산으로 배치하면 화면 밖으로 밀린다.** 부채꼴 각도를 쓰다가
  두 개가 화면 밖으로 나갔다. 엄지 닿는 자리에 좌표를 직접 박는 편이 확실하다
  (`SKILL_SLOTS`).
- **PIL의 `multiline_textbbox`는 float을 돌려준다.** 그대로 `Image.new`에 넘기면
  `TypeError: 'float' object cannot be interpreted as an integer`.
