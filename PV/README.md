# 컴스톡 PV (15초 스팀 트레일러 · 캐주얼 뱀서라이크)

사용자 콘티 6컷을 그대로 옮긴 게임 소개 영상과 그 렌더러다.
게임에 실제로 들어 있는 스프라이트·BGM·효과음만 재료로 쓰고, 프레임을 한 장씩 합성한 뒤
ffmpeg로 MP4를 뽑는다. **Unity를 켜지 않아도 돌아간다.**

## 결과물

| 파일 | 설명 |
|---|---|
| `out/comstock_pv.mp4` | 본편. 15.0초 · **1920x1080 가로(16:9)** · 30fps · 약 13MB |
| `out/comstock_pv_web.mp4` | 웹 삽입용 경량본(1280x720, 약 2.9MB) |
| `out/comstock_pv.html` | 영상 + 컷별 해설 + 제작 노트가 든 한 장짜리 페이지 |
| `out/still_*.png` | 확인용 정지 프레임 |

`out/`은 `.gitignore` 대상이다(생성물이며 용량이 크다).

## 실행

에셋이 **Git LFS**로 관리되므로 포인터 파일 상태면 PNG를 열 수 없다. 먼저 받아야 한다.

```bash
git lfs pull

pip install pillow numpy imageio-ffmpeg   # ffmpeg 바이너리 포함
python3 PV/make_pv.py                     # 본편 렌더 (약 2분 10초)
python3 PV/make_pv.py --stills            # 확인용 정지 프레임만
python3 PV/make_pv.py --preview 7.5       # 특정 시각 한 장만
python3 PV/build_page.py                  # 공유용 HTML 페이지
```

## 무엇이 "스팀 캐주얼 뱀서라이크" 톤을 만드나

세 가지다. 셋 중 하나만 빠져도 톤이 흐트러진다.

1. **가로 16:9** — PC 게임이라는 가장 빠른 신호다. 앞서 만들었던 세로 9:16은 그 자체로
   "모바일 광고"라고 말하고 있었다.
2. **모바일 조작 UI를 걷어낸다.** 조이스틱·터치 스킬 버튼·손가락 커서를 지우고 그 자리에
   **상단 경험치 바 · 웨이브 타이머 · 재화 · 좌하단 장착 무기 칸**을 넣으면 뱀서라이크
   PC HUD가 된다.
3. **자막을 낮춘다.** 광고 톤의 금색 3겹 대신 **어두운 외곽선 + 밝은 속살** 두 겹으로 하고,
   하단 그라데이션 스크림 위에 올린다. 트레일러는 게임 화면을 보여 주는 게 목적이라
   글씨가 조용해야 한다.

후처리도 절제했다. 채도 +18%(광고 톤은 +34%), 줌 펀치와 화면 흔들림은 여섯 곳만,
오디오는 -16 LUFS(광고 톤은 -13). **트레일러는 흔들리고 시끄러울수록 싸 보인다.**

장르 관용구는 오히려 더 챙겼다 — 사방으로 뿌리는 자동 사격, 중심으로 조여 오는 무리,
**빨려 들어오는 경험치 보석**, 레벨업 3택 카드.

| 02.4 | **2. 좀비가 뒤돌아본다** | 한 마리가 돌아보고 "!" → 대군단이 화면을 채운다 |
| 05.0 | **3. 잡으면서 진행** | "가만히 서 있어도 알아서 쏜다" · 자동 조준·자동 공격·재장전 없음 |
| 07.6 | **4. 게임으로 전환** | HUD가 얹히며 게임 화면이 된다 → LEVEL UP → 3장 중 1장 |
| 10.4 | **5. 장비 전환 · 각 컴스톡 · 합격** | 무기 교체 → 머리 12종 넘기기(하단 로스터) → "합격" 도장 |

## 구조

- 가로 16:9(1920x1080), 30fps.
- 장면은 `TIMELINE`이 `(시작초, 길이, 함수, 이름)`으로 들고 있다. 각 함수는 그 장면
  안에서 흐른 초를 받아 캔버스 한 장을 돌려준다.
- **`camera(canvas, zoom, fx, fy)`** — 장면 안에서의 카메라. 화면 밖으로 밀려난 것은
  잘려 나가므로, "줌아웃하면서 화면 밖에 있던 좀비 떼가 드러난다" 같은 연출을 그냥
  좌표대로 그려 두면 된다. 2번 컷의 대군단이 이 방식이다.
- **`swarm(...)`** — 중심을 향해 모여드는 무리. 뱀서라이크는 "사방에서 조여 온다"가
  핵심이라 줄 세워 걷게 하지 않고 원형으로 배치해 안쪽으로 당긴다. y 순으로 정렬해
  아래쪽이 앞에 오게 그린다.
- **`xp_gems(...)`** — 처치 지점에서 플레이어에게 빨려 들어오는 경험치 보석.
  이 장르에서 화면이 가장 기분 좋아지는 순간이라 빠뜨리면 안 된다.
- **`build_robot(head, wl, wr)`** — 5번 컷의 "각 컴스톡". `Comstock.png`는 무기까지
  통째로 그려진 한 장이라 장비를 바꿀 수 없어서, **머리(=몸통) + 다리 파츠 + 좌우
  무기**를 코드로 조립한다. 게임의 `ProceduralCharacterRig`와 같은 발상이다.
- **`draw_hud(..., alpha)`** — PC HUD. 4번 컷에서 이 값이 0→1로 올라가며 "게임으로
  전환"이 만들어진다.
- 후처리(`post`)는 줌 펀치 → 화면 흔들림 → 채도 → 대비 → 블룸 → 비네팅 →
  컷 플래시 순이다.

## 겪은 함정 (다음에 또 걸리기 쉬운 것들)

- **★ 자막·HUD는 카메라 변환 뒤에 그려야 한다.** 카메라 안에서 그리면 줌을 따라 같이
  커졌다 작아지고, 하단 자막은 화면 밖으로 밀려 잘린다. 2번 컷 자막이 줌 1.9배를
  따라다니다 화면 절반으로 밀려났었다. `camera()`를 먼저 적용하고 그 결과 위에 자막을
  얹는다.
- **★ 조립한 스프라이트를 bbox로 자르면 부품에 따라 크기가 튄다.** 5번 컷에서 무기마다
  실루엣 폭이 달라, 잘라 놓고 같은 높이로 그리니 **무기가 클수록 로봇이 작아 보였다.**
  `build_robot`은 **고정 캔버스를 그대로 반환**한다(여백만큼 작아 보이므로 배치 높이를
  1.3배쯤 키워 잡으면 된다). 단독 스프라이트는 반대로 bbox 크롭이 맞다.
- **연속 프레임을 프레임마다 따로 bbox로 자르면 안 된다.** 실루엣이 변하는 애니메이션은
  프레임마다 bbox가 달라서 그림이 매 프레임 튄다. `seq()`가 **전체 프레임의 합집합
  bbox로 한 번에** 자르는 이유다.
- **9-슬라이스 UI 패널을 `box`(비율 유지)로 맞추면 정사각형으로 쪼그라든다.** UI 패널은
  `size`(비율 무시)로 늘여야 한다. 다만 **가로로 긴 버튼을 정사각으로 늘리면 그냥
  검은 상자**가 되므로, 원형 버튼은 아예 코드로 그리는 편이 낫다.
- **균등 간격으로 깔면 떼가 격자처럼 보인다.** 칸 안에서 좌우·상하로 흩뜨려야 무리로
  읽힌다(`rank_horde`의 `(ph - 0.5)` 항).
- **낙하 연출에 `ease_in`(=k³)을 쓰면 착지 직전에야 나타난다.** 완만한 곡선(k^1.2)을
  쓰고, **낙하 중에는 카메라를 당기지 않는다**(당기면 위에서 내려오는 몸이 화면 밖에서
  잘린다). 착지 순간 확 당겼다가 푸는 게 충격을 만든다.
- **폭발·이펙트는 주인공보다 앞에 그려야 한다.** 뒤에 그리면 화면에서 사라진다.
- **클로즈업 컷에서 전경 오브젝트가 주인공을 가린다.** 2번 컷에서 컴스톡을 화면 중앙에
  뒀더니 좀비 클로즈업을 덮었다. 좌하단 전경으로 비켜 세우면 "좀비가 보고 있는 대상"
  으로만 읽힌다.
- **연속 프레임 폴더의 파일명을 확인할 것.** `RollDust/`만 `굵은001.png` 같은 한글
  이름이라 `frame_01.png` 규칙을 가정했다가 `FileNotFoundError`가 났다.
- **PIL의 `multiline_textbbox`는 float을 돌려준다.** 그대로 `Image.new`에 넘기면
  `TypeError: 'float' object cannot be interpreted as an integer`.
