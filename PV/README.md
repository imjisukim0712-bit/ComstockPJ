# 컴스톡 PV (30초 흑백 TV 광고)

1950년대 미국 흑백 TV 광고 톤으로 만든 게임 소개 영상과 그 렌더러다.
게임에 실제로 들어 있는 스프라이트·BGM·효과음만 재료로 쓰고, 프레임을 한 장씩
합성한 뒤 ffmpeg로 MP4를 뽑는다. **Unity를 켜지 않아도 돌아간다.**

## 결과물

| 파일 | 설명 |
|---|---|
| `out/comstock_pv.mp4` | 본편. 30.0초 · 1280x720 · 24fps · 약 12MB |
| `out/comstock_pv_web.mp4` | 웹 삽입용 경량본(960x540, 약 4MB) |
| `out/comstock_pv.html` | 영상 + 컷별 콘티 + 제작 노트가 든 한 장짜리 페이지 |
| `out/still_*.png` | 확인용 정지 프레임 |

`out/`은 `.gitignore` 대상이다(생성물이며 용량이 크다). 필요하면 아래 명령으로 다시 뽑는다.

## 실행

에셋이 **Git LFS**로 관리되므로 포인터 파일 상태면 PNG를 열 수 없다. 먼저 받아야 한다.

```bash
git lfs pull

pip install pillow numpy imageio-ffmpeg   # ffmpeg 바이너리 포함
python3 PV/make_pv.py                     # 본편 렌더 (약 1분 20초)
python3 PV/make_pv.py --stills            # 확인용 정지 프레임만
python3 PV/make_pv.py --preview 12.5      # 특정 시각 한 장만
python3 PV/build_page.py                  # 공유용 HTML 페이지
```

## 구조

- **콘텐츠는 4:3(960x720)으로 그린다.** 옛날 TV가 4:3이라 그렇고, 마지막에 16:9 한가운데
  필러박스로 앉힌다. 이 비율 자체가 "낡은 TV"를 가장 빨리 읽히게 하는 장치다.
- 장면은 `TIMELINE` 리스트가 `(시작초, 길이, 함수, 이름)`으로 들고 있다.
  각 함수는 그 장면 안에서 흐른 초를 받아 캔버스 한 장을 돌려준다.
- CRT 처리(`crt()`)는 흑백 변환 → 대비 강화 → 컴포지트 번짐 → 밝기 깜빡임/수직 롤바 →
  주사선 → 비네팅 → 필름 그레인 → 수평 찢김 → 정전기 폭발 → 먼지·스크래치 →
  프레임 지터 순으로 numpy에서 한 번에 돈다.
- 소리는 `build_audio()`가 ffmpeg `filter_complex` 한 방에 섞는다.

## 겪은 함정 (다음에 또 걸리기 쉬운 것들)

- **연속 프레임을 프레임마다 따로 알파 bbox로 자르면 안 된다.** 걷기·포효처럼 실루엣이
  변하는 애니메이션은 프레임마다 bbox가 달라서, 각자 잘라 같은 높이로 그리면 **그림이 매
  프레임 튄다.** `seq()`가 **전체 프레임의 합집합 bbox로 한 번에** 자르는 이유다.
  (단독 스프라이트는 개별 bbox 크롭이 맞다 - 위치를 잡기 쉬워진다.)
- **가로로 납작한 그림을 세로 기준으로만 키우면 화면 밖으로 뭉개진다.** 달리는 스프린터가
  그랬다. 몬스터 클로즈업은 `put(..., box=(w, h))`로 사각형 안에 맞춘다.
- **필름 그레인은 압축이 거의 안 먹는다.** CRF 19로 뽑았더니 30초짜리가 **81MB**였다.
  화면이 어차피 지직거리는 흑백이라 CRF 28에서도 눈에 띄는 손실 없이 12MB로 떨어진다.
- **믹스만 하고 정규화를 빼면 광고답지 않게 소심하게 들린다.** 평균 -27.8dB였다.
  `loudnorm=I=-15`을 걸어 -18.8dB / 피크 -0.8dB로 맞췄다.
- **자막과 그림은 자리를 다툰다.** 무기 격자가 하단 카운터 글씨를 덮고 있었다.
  격자를 위로 올리고 **아래쪽 176px을 자막 전용 띠로 비워** 해결했다.
- 광고의 주인공은 배경보다 **앞에** 그려야 한다. 전투 컷에서 로봇을 좀비 떼보다 먼저
  그렸더니 제품이 군중에 묻혔다.
